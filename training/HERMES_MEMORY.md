# Hermes 记忆模块（首版）

Orvyth 已接入 Hermes Agent 实际的 MemoryStore 和威胁扫描源码，保留其 MIT 许可。此版本接入记忆组件，不启动 Hermes 完整 Agent、CLI、网关、定时任务、子代理或自动技能生成；Pi 继续处理现有文件任务。

## 使用

重启网页版，在原聊天框发送：

- `记住：我喜欢简短的回答，不要表情符号`
- `记住：我的项目代号是青松42`
- `查看记忆`
- `忘记第1条`
- `忘记：我喜欢简短的回答，不要表情符号`
- `清空所有记忆`

仅明确的记住请求会写入，不自动分析所有聊天来保存。每条最多400字，用户偏好总量最多3000字符，重复内容不重复追加。容量或扫描失败时会明确提示。保存的资料在每次普通模型回复前加载，跨新聊天和服务重启有效，实际是否遵从仍取决于模型。文件任务不额外启动Hermes模型循环。

记忆位于当前数据库旁的 `hermes-memory/<账户ID的SHA256>/USER.md`。每个本机Cookie账户独立；命令在后端执行，记忆文件使用原子替换和文件锁。适配器用ContextVar隔离并发请求的数据目录，不修改全局HERMES_HOME。个人记忆问题不调用联网搜索。

删除记忆不删除聊天原消息，因此当前对话历史里仍可能有该信息；要验证遗忘可以新建聊天。反之，删除聊天也不删除独立记忆，需要用上述记忆命令管理。没有云端同步，也不修改模型权重。

## 来源与维护

`hermes_memory_vendor/` 保存官方仓库下载的固定源码快照、LICENSE、原始SHA256和来源链接。上游来源为 `NousResearch/hermes-agent/tools/memory_tool_store.py` 与 `tools/threat_patterns.py`。本地只调整导入到私有命名空间，并以 `compat.py` 适配原子文件写入、目录隔离和锁依赖。没有安装Hermes全量依赖，不改现有Python、Ollama或模型。

自动测试覆盖记忆持久化、账户隔离、并发目录隔离、重复追加、删除、清空以及真实HTTP聊天中新会话加载偏好。测试目录与用户实际数据隔离。
