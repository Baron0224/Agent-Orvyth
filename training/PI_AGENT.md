# Orvyth 聊天中的文件读取（Pi）

已接入官方 `@earendil-works/pi-coding-agent` SDK 1.5.0，由 Python 后端启动独立 Node 进程。继续使用本机 Ollama。当前默认聊天为 `qwen3:8b`，文件工具保留已验证的 `qwen3:8b`，可通过 `--tool-model` 独立指定；显式切换Qwen聊天时工具默认跟随该Qwen。R1在本机报告工具能力，但本次不以其替换既有Pi工具路径。

## 使用

1. 重启 `chat_web.cmd`，刷新网页。
2. 直接在聊天框说：`帮我读取 "D:\GitHub work\OpenAgent\OpenAgent\training\pi\package.json"，告诉我 Pi 依赖版本。`
3. 也可以说“读取我文档里 Three Feet Under 中的故事背景”。程序先按名称查找文档、桌面、OneDrive 对应目录及当前项目周边目录，唯一结果直接读取，多个结果让你回复序号；未定位到时可补充更具体的文件名或所在文件夹。文件夹路径也可用于目录总结。有空格的完整路径请加双引号。
4. 回复会在原聊天中显示，并保存在本机聊天记录中。缺少文件或无法读取时会明确提示。

Pi 隐藏在后台，没有独立的项目助手按钮或面板。读取时聊天气泡显示进度。每次文件任务使用临时 Pi 会话，模型根据本轮要求及补充路径执行，后台最多运行三分钟；当前不支持对已读文件内容做任意多轮工具任务，需要重新明确读取要求。普通聊天继续使用原模型流程。

也支持明确的新建桌面文本请求，例如“在桌面新建文档，名字叫‘你好’，内容是‘我爱你’”（建议使用中文双引号）。程序读取系统真实桌面位置，新建 UTF-8 的 `你好.txt`，写入成功后才回复位置，并将结果保存到聊天。新建操作由后端执行，不依赖模型声称成功；同名文件不覆盖。支持 .txt，不支持创建Word文档、修改既有文件或执行脚本。缺文件名或内容时会询问。

## 换电脑安装

需要 Node.js 22.19 或更新版本、Python 环境、Ollama 和已下载模型。在 `training/pi` 目录运行：

```powershell
npm ci --ignore-scripts
```

依赖锁定在 package-lock.json；node_modules 不提交。Pi 本身采用 MIT 许可，模型的许可另计。当前只请求本机 Ollama，不需要第三方模型密钥。通过原有启动参数 `--model 模型名` 可改用其他已下载模型，但工具调用能力需要实际验证。

## 当前能力和范围

Pi 提供 `list_project` 和 `read_project`，只读指定目录内文本；指定单文件时仅开放该文件。解析真实路径以阻止软链接越界；不加载项目或用户的 Pi 扩展、配置、技能、MCP 和指令文件。过滤常见密钥和数据库文件，每次最多12次读取、每文件256KB、输出12000字符。过滤不是通用秘密识别器，普通源码中的敏感内容仍可能送给本机模型。Pi模型没有自由写文件或执行命令工具；上方的桌面新建文本请求由后端解析后单独执行。

自动查找只匹配文件/文件夹名称，不做全盘内容搜索，不遍历符号链接、依赖及缓存目录。最多查找3秒、30000个目录项、6层目录，返回至多8个匹配，所以“未定位到”不代表全盘不存在该文件。可用 `ORVYTH_FILE_ROOTS` 环境变量指定其他查找根目录（Windows 用分号分隔），重启服务后生效。

常用查找位置也包含 C/D/E/F 盘上已存在的 Codex、Projects 目录。支持“帮我找到某项目的文档”及随后补充“在d盘codex的three feet under里”；即使上一条旧模型回复错误，也会接续最近明确的文件请求。提到项目里的“故事背景”等具体文档时，会在项目内继续按文档名定位，找到唯一文件后才交给 Pi 读取。

本机 Qwen 4B 已实际完成文件读取和版本问答，但出现过名称拼写偏差，不能据此认定复杂任务可靠。如果模型没调用文件工具，界面会标记未核实；超时和模型错误显示任务未完成。后续可增加审核后的文件修改能力。
